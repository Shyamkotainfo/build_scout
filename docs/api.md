# BuildSmart — API Reference

> **Source of truth**: The code in `backend/api/` and `backend/models/schemas.py`.
> This document reflects the **currently implemented** API only.

---

## Base URL

```
http://127.0.0.1:8000
```

---

## Documentation Endpoints

These are automatically generated by FastAPI and always available:

| Endpoint | Description |
|---|---|
| `GET /docs` | Swagger UI |
| `GET /redoc` | ReDoc UI |
| `GET /openapi.json` | Raw OpenAPI 3.x schema |

## Business Endpoints

There are exactly **3 business endpoints** currently implemented.

---

### 1. GET /health

**Purpose**: Liveness check.

**Request**: No body, no parameters.

**Response (200)**:
```json
{"status": "healthy"}
```

**Example**:
```bash
curl http://127.0.0.1:8000/health
```

---

### 2. POST /api/v1/analyses

**Purpose**: Submit a user request and run the full BuildSmart agentic workflow.

Executes the complete pipeline:
```
FastAPI → AnalysisService → LangGraph → 7 Agents → Lakebase persistence → Response
```

> ⚠️ MCP is **not currently active**. `candidates` and `evaluations` will be empty lists.

**Request Body** (`application/json`):
```json
{
  "user_request": "I want to build an AI document intelligence platform..."
}
```

| Field | Type | Required | Constraints |
|---|---|---|---|
| `user_request` | `string` | ✅ | 1–5000 chars, stripped of whitespace |

**Response (200)** — `AnalysisResultResponse`:
```json
{
  "analysis_id": "7a372f22-233c-453f-b8ee-a5975ddcc03a",
  "user_request": "I want to build...",
  "normalized_request": "AI document intelligence platform",
  "domain": "document_intelligence",
  "status": "VALIDATED",
  "requirements": [...],
  "components": [...],
  "candidates": [],
  "evaluations": [],
  "decisions": [...],
  "blueprint": {...},
  "validation_result": {...},
  "agent_history": [
    "SupervisorAgent", "DecompositionAgent", "ResearchAgent",
    "EvaluationAgent", "DecisionAgent", "BlueprintAgent", "ValidationAgent"
  ],
  "traces": []
}
```

**Error Responses**:

| Code | Error Code | Condition |
|---|---|---|
| 422 | `INVALID_REQUEST` | Missing/invalid `user_request` |
| 503 | `LLM_SERVICE_UNAVAILABLE` | Groq API unreachable or rate-limited |
| 500 | `ANALYSIS_EXECUTION_FAILED` | LangGraph workflow error |
| 500 | `INTERNAL_ERROR` | Unexpected server error |

**Example**:
```bash
curl -X POST http://127.0.0.1:8000/api/v1/analyses \
  -H "Content-Type: application/json" \
  -d '{"user_request": "Build an AI document intelligence platform"}'
```

---

### 3. GET /api/v1/analyses/{analysis_id}

**Purpose**: Retrieve a previously completed analysis from Databricks Lakebase.

> **IMPORTANT**: This endpoint reads **only** from the database. It does **NOT**:
> - Execute the LangGraph workflow
> - Invoke any agent
> - Call the LLM
> - Call MCP tools

**Path Parameter**:

| Parameter | Type | Description |
|---|---|---|
| `analysis_id` | `string` (UUID) | ID returned from `POST /api/v1/analyses` |

**Response (200)** — Same `AnalysisResultResponse` schema as POST.

**Error Responses**:

| Code | Error Code | Condition |
|---|---|---|
| 404 | `ANALYSIS_NOT_FOUND` | `analysis_id` does not exist in Lakebase |
| 503 | `DATABASE_NOT_CONFIGURED` | Lakebase env vars not set |
| 500 | `DATABASE_RETRIEVAL_FAILED` | Database error during retrieval |
| 500 | `INTERNAL_ERROR` | Unexpected server error |

**Example — retrieve existing analysis**:
```bash
curl "http://127.0.0.1:8000/api/v1/analyses/7a372f22-233c-453f-b8ee-a5975ddcc03a"
```

**Example — 404 response**:
```bash
curl "http://127.0.0.1:8000/api/v1/analyses/00000000-0000-0000-0000-000000000000"
# → HTTP 404
# → {"error": {"code": "ANALYSIS_NOT_FOUND", "message": "Analysis with the specified ID was not found."}}
```

---

## Error Response Schema

All errors use the same structure:

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "Human-readable message.",
    "details": { ... },
    "analysis_id": "optional-uuid"
  }
}
```

Defined in `backend/models/schemas.py` as `ErrorResponse` / `ErrorDetail`.
